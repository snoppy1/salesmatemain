- **เพิ่มตัวเลขใหม่ (commit a1f2b82): "AI มีส่วนช่วยขาย"** — ฐานกว้างกว่าพ่วง: นับ**ทุกสินค้าที่ AI ส่งการ์ดในแชตแล้วมีออเดอร์ตามมา** (การ์ด ~38 ใบ/สัปดาห์ vs เสนอพ่วง 6 ครั้ง = โอกาสเห็นเลข ~6 เท่า) · ตาราง `assist_matches` (UNIQUE shop+order+item กันนับซ้ำ) · โชว์การ์ดเขียว + คอลัมน์ในแท็บยอดขาย AI
- **ข้อ 2+3 ที่ลูกค้าอยากได้ มีอยู่แล้วใน HomeTab (แท็บแรก admin):** เวลาตอบเฉลี่ย, ตอบนอกเวลาทำการ, AI ตอบแทนคน %, ชม.ที่ประหยัด — เป็นตัวเลขวัดตรง 100% เอาไปโชว์ลูกค้าได้เลย
- **รอผล:** แมตช์แรก (พ่วง + assist) คาดเห็นราว 29 ก.ค. ถ้าผ่านไปแล้วยัง 0 ทั้งที่ร้านมีออเดอร์ปกติ → สงสัยตัวดึงออเดอร์ Lazada บน prod error เงียบ (เทสจากเครื่องไม่ได้ คีย์ laz1 อยู่ Vercel เท่านั้น) แผนถัดไปคือเพิ่มตัวเลข "ออเดอร์ที่เช็คแล้ว" ในหน้าสถานะระบบ (งานเล็ก ขอถามก่อน)

### Security hardening (commit e3dd8bf)
- **Rate limit** ผ่าน `lib/throttle.ts` (นับใน Postgres ตาราง `auth_throttle`): login 5/15นาที/อีเมล + 20/IP · signup 5/ชม./IP · forgot 10/15นาที/IP — **ทดสอบจริงบน prod ผ่าน** (401 ×5 → 429)
- **Session** 30 → 14 วัน
- **เพดานสินค้า** ≤1,000 ชิ้น + จำกัดความยาวฟิลด์ + รูปรับเฉพาะ `data:image/`≤650KB หรือลิงก์ http (กันยัด `javascript:`)
- **ยืนยันแล้ว:** React escape ทุกจุด (HTML ดิบมีที่เดียวคือ theme-init ของเราเอง) → สคริปต์ในชื่อสินค้าทำงานไม่ได้
- **checklist ที่ยังไม่ทำ (ยังไม่คุ้มช่วงเบต้า):** ตรวจรูป NSFW, WAF (Cloudflare), nonce CSP — ทำตอนเปิดกว้างเกิน allowlist

### กฎสี/ตัวเลือกสินค้า (25 ก.ค. — feedback ร้าน Smarttech)
- **ปัญหา:** ลูกค้าถาม "ถ่าน AA สีส้มกับสีเขียวต่างกันยังไง" — จริงๆ เป็นตัวเลือกสีของ Beston ตัวเดียวกัน แต่ AI มโนว่าสีเขียวคือ Xtar แล้วอธิบายความต่างที่ไม่มีจริง (ให้ข้อมูลผิดกับลูกค้า)
- **สาเหตุ:** (1) import Lazada อ่านแค่ `skus[0]` — ข้อมูลตัวเลือกสี/แบบถูกทิ้งหมด AI ไม่มีทางรู้ (2) prompt ไม่มีกฎกันเดาเรื่องสี
- **แก้แล้ว:** `extractVariantOptions` ใน `lib/marketplace.ts` เก็บตัวเลือกจากทุก SKU (`saleProp`) → ต่อท้าย description เป็น "มีให้เลือก: สีส้ม/สีเขียว" (เพดาน 8 ตัวเลือก กัน token บวม) — ต่อ **หลัง** AI ย่อ desc (`withVariantNote`) กันโดนตัดทิ้ง ครอบทั้งขา import และขา sync (สินค้าใหม่) + กฎ 1.2 ใน REPLY prompt: ตัวเลือกสีเดียวกันสเปกเดียวกัน ห้ามเดาว่าสีที่ลูกค้าพูดคือสินค้าคนละรุ่น ไม่มีข้อมูลให้ถามกลับ
- **Gate ผ่าน 4/4** (`VARIANT_GATE=1 npx vitest run test/variant-gate.test.ts`): มีข้อมูลสี→ตอบตัวเดียวกันต่างแค่สี · ไม่มีข้อมูล→ถามกลับไม่มโน · เช็คสต๊อกสีเขียว→โยงถูกตัว · control เทียบ Beston/Xtar ยังทำได้ปกติ
- **อัพเกรดต่อ (คำขอเจ้าของ): ราคาต่อตัวเลือก** — ราคาไม่เท่ากันระหว่างตัวเลือก → note ระบุราคาต่อตัว เช่น "มีให้เลือก: สีส้ม 499 บาท/สีเขียว 520 บาท" (เท่ากันทุกตัว = ไม่ซ้ำราคา ประหยัด token) + กฎ 1.2 สั่งใช้ราคาตามตัวเลือกตอนแจ้ง/คิดรวม — gate รวมผ่าน 7/7 (เคสเด็ด: สีเขียว 2 ชุด → 520×2=1,040 ไม่หลงใช้ราคากลาง 499)
- **sync 45 วิ เติม/รีเฟรช note เองอัตโนมัติ** (`replaceVariantNote` ใน `syncProductsStock`) — ร้านไม่ต้อง re-import เลย + ราคาโปรฯ Lazada แกว่งก็ไม่มีราคาค้างเก่าใน note · log ใน `product_sync_changes` เป็น "ตัวเลือกสินค้า" (ไม่ใช่จุดแคช — description อยู่บล็อกไม่แคชของร้าน retrieval) · variantOptions ว่าง = ไม่แตะ description (กันลบข้อความที่ร้านเขียนเอง)
- **ต้นทุน (เจ้าของถาม 25 ก.ค.):** note ไม่เข้าดัชนีก้อนแคช → ความถี่เขียนแคชใหม่ไม่เพิ่ม (ยกเว้นร้าน ≤24 สินค้า ที่คลังเต็มอยู่ในแคช — ก้อนจิ๋ว ค่าระดับสตางค์) · กันเพิ่ม: sort ตัวเลือกให้ note นิ่งเป็น byte เดิมทุก sync แม้ Lazada สลับลำดับ SKU (แนวเดียวกับ canonPrice)
